# 稳定性与安全修复计划

## 范围

保留 Express、原生浏览器界面和本机 CPA 代理的产品结构，逐项修复审查发现的 13 项问题，并改进上下文一致性、扫描与渲染性能、可维护性和启动体验。不修改 CPA、Keeper 或 Codex 的配置，不引入数据库迁移。

## 分阶段交付

| 阶段 | 范围 | 验证 |
| --- | --- | --- |
| 请求生命周期 | 单次收尾、会话与选择隔离、前后端取消、异常结束 | Node 回归测试、流式协议测试 |
| 安全边界 | 同源与请求校验、仓库身份、符号链接、Markdown 和 DOM | API 集成测试、浏览器安全用例 |
| Git 与 Diff | 新增目录和特殊路径、首次提交、引用区间、hunk 解析、截断 | 临时 Git 仓库的真实行为测试 |
| 计量与健康 | 最新配额窗口、错误可见性、可配置依赖 | 内存 SQLite 与代理响应测试 |
| 分析上下文 | 有期限的服务端快照、历史预算、版本一致的证据 | 快照变更和多轮请求测试 |
| 工程与体验 | 本地固定版本资源、安全启动、模块边界、窄屏、文档 | 构建检查、浏览器端到端、服务启动检查 |

每阶段验证通过后形成独立提交并推送现有远端，再进行下一阶段。完成记录见下文。

## 架构与约束

- Git 使用参数数组执行，失败和超限显式返回；不把部分 stdout 当作完整结果。
- API 仅访问本机界面授权的规范化仓库路径；读取文件时拒绝符号链接和敏感文件。
- 浏览器状态按选择、会话和请求编号隔离；只接受当前请求的事件。
- 模型输出先净化再渲染；生成内容不能变成可执行事件属性。
- 多轮分析使用首次请求的服务端快照，文档和代码使用一致版本，缓存有容量和期限限制。
- Keeper 始终只读；依赖失败必须可见，不展示未经验证的就绪状态。

## 运行验证与恢复

现有 3300 服务在开发期间保持运行。修改完成后先使用空闲端口验证新版本，再仅替换已确认属于本项目的 3300 进程；不触碰 CPA、Keeper 或其他服务。浏览器测试使用模拟模型响应，真实代理的健康验证与测试替身的结果分别记录。

## 完成记录

- 请求生命周期：已实现单次收尾、旧响应隔离、控制器归属检查、客户端断连与业务超时；9 项 Node 回归检查与语法检查通过。后续阶段按上表推进。

- Git 与 Diff：参数数组、禁用外部 Diff/textconv、NUL 安全路径与提交日志、首次提交与区间校验、hunk 计数、预算截断、明确超限及排除提示已完成；扫描增加有限并发、短缓存和请求合并。28 项 Node 检查通过，包括真实 Git 仓库与 HTTP 断连取消。服务已支持注入测试配置，测试不会读取其他仓库或调用真实模型。

- 计量与健康：Keeper 使用参数数组和只读 JSON 查询，按账号/窗口选取最新记录；小数与未知/过期状态保留。模型失败不再返回假预设，界面可重试并禁用分析。代理地址、认证、Keeper 路径与超时已配置化，原认证值保存在忽略的本地文件；31 项 Node 和 2 项 Chromium 检查通过。

- 分析上下文：首次请求生成 30 分钟、最多 24 份的服务端快照，追问复用固定证据；历史仅允许 user/assistant，按完整轮次裁剪到 24k 字符。历史版本使用 regular Git blob 读取文档与源码，工作区捕获期间检测变化；文档/源码明确行号与截断，干净工作区回退返回实际 SHA。已配置的认证值在历史 Diff 和模型证据中脱敏。35 项 Node 检查通过，包括修改工作区后追问、版本文档、链接 blob、期限/容量与历史注入验证。
