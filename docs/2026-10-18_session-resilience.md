# 2026-10-18 长会话与证据质量修复

## 范围

本轮在 `589cdff` 之后，处理通读代码时复现的问题，并改进模型拿到的证据质量：

1. 快照固定 30 分钟过期，长时间阅读后的追问直接失败，对话只能清空重来。
2. 页面发送全部历史，服务端只用最近 24k 字符却按全部历史校验；对话超过 100 条消息或 30 万字符后，每次追问都返回 400。
3. 服务重启后内存令牌失效，页面一直 401，必须手动刷新。
4. 未加引号的 Diff 头在路径含 ` b/` 且没有内容行时（如仅修改权限）解析出错误路径；复制（copy）元数据未识别。
5. 证据文件先 `git show` 全量读取再判断大小，超大文件仍会占满 8 MiB 输出缓冲。
6. 目录选择没有超时，原生对话框不返回时请求一直挂起；`commits` / `diff` 超时返回通用消息。

同时完成以下改进：上下文改为分节文本、Diff 标注行号、子目录指令文档优先、提示词统一由服务端维护、Keeper 显示 Claude 用量、追问快捷按钮随模式变化。

## 修复内容

### 快照生命周期

- `SnapshotStore` 改为滑动期限：每次读取续期 30 分钟，并移到 LRU 尾部；超出 24 份时回收最久未用的快照。
- 过期或被回收时返回 409，并附带 `code: 'snapshot-expired'`（`httpError` 新增可选 `code`）。与“快照和当前选择不一致”的 409 区分开。
- 已有对话时，客户端收到 `snapshot-expired` 会带 `renewSnapshot: true` 自动重试一次。服务端重新捕获证据并保留历史，同时告诉模型这是会话中途的新快照，早先回答可能基于旧证据。回答底部注明“分析快照已在会话中重新捕获”。
- 没有 `snapshotId` 却带历史的请求，只有 `renewSnapshot` 为真时才接受；`renewSnapshot` 必须是布尔值。

### 历史与会话

- 页面按完整轮次从尾部截取 24k 字符以内的历史发送；完整对话保留在页面，用于复制和导出。发生裁剪时状态栏会提示。
- `apiFetch` 收到 401 后丢弃缓存的本机会话，重新获取令牌并重试一次。

### Diff 与证据

- `splitPlainHeader` 先按 `a/X b/X` 等长对称拆分，匹配不上再回退到正则；识别 `copy from` / `copy to`。
- 新增 `numberDiffLines`：发给模型的 Diff 每行带真实行号（`+新行号|`、`-旧行号|`、` 新行号|`）。页面显示的 Diff 不变。
- `readVersionText` 先用 `ls-tree -l` 读取对象大小，超过 500 kB 时直接拒绝，不再读取内容。
- 改动路径上的 `AGENTS.md` / `CLAUDE.md` 按目录从深到浅排序，排在通用项目文档和清单之前进入预算，最多 40 份。
- 上下文从 JSON 改为分节文本（`<warnings>`、`<diff>`、`<document>`、`<source>`），证据内容里的同名标签会被转义，不能提前闭合分节。系统提示要求以证据中标注的行号为准。

### 提示词与界面

- 四个精读动作的提示词只保存在服务端 `MODES`。客户端只发送 `mode`，按钮文字作为用户气泡显示；服务端在 `snapshot` 事件中回传实际指令，对话历史记录这条指令。
- 自定义问题去掉首尾空白后为空时返回 400。
- 追问快捷按钮：苏格拉底考题模式下第一个按钮为“展开自测考题推演与答案”，其他模式下为“出两道自测题检验理解”。
- Keeper 状态栏和详情弹窗增加 Claude 用量卡片。

### 服务端

- 目录选择使用 `requestLifecycle`，默认 5 分钟超时，可通过 `pickTimeoutMs` 配置，超时返回 504。
- `requestLifecycle` 支持自定义超时消息；`pick` / `commits` / `diff` 改用统一的 `sendFailure`，超时返回 504 和具体说明。

## 保留边界

- 快照仍保存在内存中；续建得到的是当前证据，不能恢复原快照，因此回答底部会明确标注。
- 历史裁剪按字符数估算，不是模型 token 数；被裁掉的早期轮次模型看不到。
- Diff 行号只加在发给模型的文本上，页面仍显示原始 patch。
- 本地令牌仍不是多用户权限系统；证据仍按预算截断，回答不能当作完整的仓库审查。
